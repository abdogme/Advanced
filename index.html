📚 ملخص Lecture 1 — Arrays & Methods

1. هياكل البيانات — Arrays

  • Array: حاوية ذات حجم ثابت تخزن عناصر من نفس النوع. في Java تُعامَل كـ Object.
  • 1D Array: يشبه Vector List. 2D Array: يعمل كـ Matrix.
  • منطق الـ Matrix: تستخدم الـ 2D Array مؤشرَين: row (أفقي) و column (عمودي).
  • العناصر القطرية (Diagonal): في مصفوفة مربعة (مثل 3×3)، العناصر على القطر الرئيسي تتحقق عندما i == j.
  • القيم الافتراضية: للـ int تكون 0، وللـ boolean تكون false.
  • ArrayIndexOutOfBoundsException: Java تتحقق من حدود المصفوفة أثناء التشغيل. الوصول لـ a[5] في مصفوفة بحجم 5 يُسبب هذا الخطأ.
  • الذاكرة: Arrays تُخزَّن في Heap، بينما المتغير المرجعي يعيش في Stack.

2. تشريح الـ Method

  • Access Modifier: عادةً public.
  • static: يعني أن الـ method تنتمي للـ class وليس للـ object — يمكن استدعاؤها بدون إنشاء object.
  • Return Type: يمكن أن يكون primitive مثل int, double أو void إذا لم تُرجع شيئاً.
  • Parameters: المدخلات التي تقبلها الـ method.
  • Static vs Non-Static: الـ static method (مثل main) لا تستطيع استدعاء non-static method مباشرةً بدون instance من الـ class.

3. مثال Trace — Diagonal

  for (int j = 0; j < 3; j++) {
    if (i == j) System.out.print(a[i][j]);
  }
}
// Output: 1 5 9 (القطر الرئيسي)

⚠️ لو الشرط كان i <= 3 سيحدث ArrayIndexOutOfBoundsException لأن آخر index صحيح هو 2.

📚 ملخص Lecture 2 — OOP Pillars

1. Objects & Classes

  • Object: نسخة أو instance من الـ Class.
  • Syntax: ClassName objectName = new ClassName();
  • الوصول للأعضاء: عبر نقطة الوصول الدوت: object.variable أو object.method().

2. Access Modifiers & Encapsulation

  • Encapsulation: إخفاء البيانات داخل الـ class لحمايتها من التدخل الخارجي.
  • public: مرئي داخل وخارج الـ class.
  • private: مرئي فقط داخل نفس الـ class.
  • Getter (Accessor): يستخدم return x لإرجاع القيمة.
  • Setter (Mutator): يستخدم this.x = x لتعيين القيمة.

3. Constructors

  • له نفس اسم الـ class بالضبط وليس له return type (حتى void).
  • يُنفَّذ تلقائياً عند استخدام الـ new keyword.
  • No-arg: public A() { ... }
  • Parameterized: public A(int x) { ... }

4. Inheritance & Relations

  • Inheritance ("is-a"): Child class ترث من Parent class باستخدام extends.
  • Constructor Chaining: عند إنشاء object من Child، يُنفَّذ Parent constructor أولاً.
  • Private Access: Child لا تستطيع الوصول المباشر لـ private variables في Parent — تستخدم getters/setters.
  • Aggregation (weak has-a): مثل Person لديه Student ID (كلاهما مستقل).
  • Composition (strong has-a): مثل Car-Engine — Engine لا توجد بدون Car.

  public A(int x) { System.out.print("Red " + x + " "); }
}

// new A(7) → Red 7
// Output: Hello Red 7 Done

Lecture 3 — Polymorphism

Method Overloading · Method Overriding · Upcasting · Downcasting · super · Runtime Dispatch

📚 ملخص Lecture 3 — Polymorphism

1. Method Overloading

  • تعريف: أكثر من method بنفس الاسم لكن بـ parameter list مختلفة في نفس الـ class.
  • الاختلاف: في عدد الـ parameters أو نوع بياناتها.
  • مثال: m1() vs m1(int x, int y) vs m1(double x, double y).

2. Method Overriding

  • تعريف: method معرَّفة في Parent class تُعاد تعريفها في Child class.
  • القواعد: نفس الـ signature (الاسم والـ parameters) لكن implementation مختلف.
  • الاستخدام: لإعطاء سلوك خاص للـ child class.

3. Object Compatibility & Casting

  • Upcasting: Parent reference تشير لـ child object — دايماً صح. مثال: Fruit f = new Apple();
  • Downcasting: Child reference لا تستطيع تلقائياً الإشارة لـ parent object. Apple p = new Fruit(); → Error!

4. super Keyword

  • super(r) — يستدعي Parent constructor مع parameter.
  • super.Area() — يستدعي نسخة Parent من الـ method المُعاد تعريفها.
  • في Inheritance: لو Parent لديه parameterized constructor، Child يجب أن يستدعيه صريحاً بـ super.

5. Runtime Dispatch

الـ Compiler يتحقق من الـ methods المتاحة بناءً على reference type (الجانب الأيسر)، لكن الـ JVM ينفذ النسخة بناءً على actual object type (الجانب الأيمن).

6. مثال Trace

class A { public A() { print("Hello "); } public void m1() { print("green "); } }
class B extends A { public B() { print("hero "); } public void m1() { print("white "); } }

A a1 = new A(); a1.m1(); → Hello green
B b1 = new B(); b1.m1(); → Hello hero white

abstract keyword · interface · implements · public static final · Multiple interfaces · Shape hierarchy

📚 ملخص Lecture 4 — Abstract & Interfaces

1. Abstract Classes

  • تعريف: class تحتوي على method واحدة على الأقل بدون implementation (abstract method).
  • لا يمكن إنشاء object: new Shape() → Compile Error.
  • قاعدة الوراثة: أي class تعمل extends لـ abstract class يجب أن تُعيد تعريف كل abstract methods.
  • Partial Implementation: لو Child لم تُعيد تعريف كل الـ abstract methods، يجب إعلانها abstract أيضاً.

2. Interfaces

  • تعريف: تشبه الـ class لكن كل methods فيها abstract بشكل افتراضي.
  • Constants: كل data fields (variables) في الـ interface تكون تلقائياً public static final.
  • Multiple Implementation: على عكس الـ classes، class واحدة يمكنها implements أكثر من interface.
  • المطلوب: أي class تُنفذ interface يجب أن تُعيد تعريف كل abstract method فيها.
  • الكلمة المفتاحية: implements (وليس extends).

3. Abstract vs Interface

  • Abstract Class: استخدمها لما الـ classes تشترك في base مشترك وحالة (state).
  • Interface: استخدمها لما classes من hierarchies مختلفة تحتاج لتشارك سلوك مشترك (behavior).
  • يمكن إنشاء reference من نوع abstract: Shape c = new Circle(); — صح. لكن new Shape(); — خطأ.

4. مثال Trace — Shape Hierarchy

abstract class Shape {
  public abstract double Area();
  public abstract double Perimeter();
}
class Circle extends Shape {
  private double r;
  public void setr(double r) { this.r = r; }
  public double Area() { return 3.14 * r * r; }
  public double Perimeter() { return 2 * 3.14 * r; }
}
// Circle c = new Circle();
// c.setr(3.0);
// c.Area() → 3.14 × 3 × 3 = 28.26
// ⚠️ لو Circle نسيت Perimeter() → Compile Error
